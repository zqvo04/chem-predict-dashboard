# GPU를 파이프라인 어디에 쓸 것인가 — 미결 탐색

**상태: 보류. 결정하지 않았다.** 이 문서는 설계가 아니라 **재개용 기록**이다.
다음 세션이 같은 논의를 처음부터 다시 하지 않도록, 이미 측정된 것과 이미 좁혀진 선택지를
남긴다. 착수하려면 §8의 열린 질문 두 개에 먼저 답해야 한다.

작성: 2026-08-09 · 근거: [STATE.md](../../../STATE.md) §2b·§4b·§4c·§4d·§6 · [ROADMAP.md](../../../ROADMAP.md) §7

---

## 1. 먼저 측정한 것 — 현재 파이프라인은 결정적이다

```bash
python -c "
from src import funnel
smis = ['N#CC[C@H](C1CCCC1)n1cc(-c2ncnc3[nH]ccc23)cn1','CCO','c1ccccc1']
a, b = funnel.score_molecules(smis), funnel.score_molecules(smis)
print(all((a[c]==b[c]).all() for c in a.columns if a[c].dtype.kind=='f'))"
```

같은 SMILES를 두 번 채점하면 **모든 수치가 완전히 동일하다.** 시드 없는 난수는 `src/`에
하나도 없다 — 모델은 전부 `random_state=0`, `negatives._matched_indices`는
`default_rng(MATCH_SEED=0)`, `scaffold_split`은 `random.Random(seed)`. 배포 경로는 커밋된
pickle을 로드하므로 학습 자체를 하지 않는다(`model_id` = `CHEMBL2835@61edd879da`,
게이트 임계 = 0.5440278531536779).

**GPU가 들어오면 이 성질이 깨진다.**

| | 결정적? | 대응 |
|---|---|---|
| 현재 CPU 파이프라인 | ✅ | — |
| 도킹 | ❌ 확률적 탐색 | 시드 고정 + exhaustiveness 상향 + **점수를 자산으로 커밋** |
| chemprop 학습 | ❌ GPU 비결정성 | 시드를 고정해도 완전 재현은 어렵다 → **가중치 자체를 커밋** |

> **연결성 규칙(ROADMAP §3)이 성능 장치가 아니라 정확성 장치인 이유가 이것이다.** GPU
> 산출물은 재계산 대상이 아니라 **한 번 만들어 커밋하는 자산**이어야 파이프라인 전체의
> 결정성이 유지된다.

## 2. ROADMAP이 적어 둔 GPU 계획 (§7)

기준: **GPU는 "CPU로 못 하는 것"에만 붙는다. "더 빠르게"는 논거가 아니다.**

| # | 위치 | GPU가 필요한 진짜 이유 | 선행조건 |
|---|---|---|---|
| **G-1** | Stage 5 도킹 | gnina의 **CNN 리스코어링이 GPU 네이티브** | 없음 |
| G-2 | Stage 2 chemprop | D-MPNN 학습은 CPU로 비현실적 | F + A2 |
| G-3 | Stage 3 생성 모델 | 파인튜닝 | G-1 통과 시 |
| (부수) | Stage 0 구조 | AlphaFold DB에 이미 있음 → 불필요 | 새 패널 때만 |

쓰지 않기로 한 곳: 10⁶ 라이브러리 스크리닝(CPU 몇 분) · 배포 앱(영구 CPU) ·
FEP/MD(쌍당 수 시간, 무료 티어와 불일치).

무료 T4 예산: 414 × 3 아이소폼 = 1,242회 → 한 세션.

## 3. 그 사이 측정이 바꾼 것

### 3a. G-1의 값이 올라갔다

§2b가 게이트 A/B를 반증하면서 원인을 특정했다 — **게이트의 실패는 라벨 클래스가 아니라
표현의 한계다.** 회귀·게이트·AD·컨포멀 네 층이 전부 같은 ECFP4 2048비트에서 나오고,
JAK 논문의 측정 비결합자는 활성 유사체와 같은 지문 이웃에 있다.

**도킹은 그 병목을 지나지 않는 유일한 경로다**(ROADMAP D5의 "직교 증거").

### 3b. 이전 판단 정정 — G-2를 과잉 강등했다

2026-08-09 이전 대화에서 "§4b(학습 곡선 포화)와 §4d(파라로그 전이 0.472)가 G-2를
강등한다"고 적었다. **과잉 해석이다.**

두 측정 모두 **ECFP4+GBM으로** 돌렸다. 즉 잰 것은 "이 표현으로는 데이터를 더 넣어도 안
는다"이지 "데이터가 소진됐다"가 아니다. §2b가 표현을 병목으로 지목했으므로 두 결과는
모순이 아니라 같은 얘기다 — **표현이 막고 있어서 데이터가 안 먹힌다.**

따라서 §4b·§4d는 G-2의 반증이 아니라, 조건부 근거다.

### 3c. G-3은 더 낮아졌다

생성 분자는 현재 같은 ECFP4 모델로 채점된다. §2b가 그 모델이 결합/비결합을 못 본다고
측정했으므로, **채점할 수 없는 채점기에게 분자를 더 만들어 주면 잡음이 증폭된다.**

추가로 ROADMAP §2가 기여의 원천을 채널 ②(ChEMBL에 있으나 JAK 미측정, 38,592개)로
지목했고 G-3은 채널 ③을 키우는 일이다. 그리고 채널 ②에는 아직 MAKE 단계(구매가능성)조차
없다.

## 5. 더 큰 논거 — 일반화

§4까지는 도킹을 JAK의 확인층으로만 본 것이고, 그건 한계적 개선이다. **진짜 논거는 다른 데
있다.**

### 5a. 이 저장소의 일반화는 명목상이다 (STATE §6)

| 자산 | jak | pi3k |
|---|---|---|
| 아이소폼 parquet | 3 ✅ | 4 ✅ |
| `cross_measured` | 3,624 ✅ | 1,500 ✅ |
| 회귀모델 · 게이트 · AD · 컨포멀 · negatives | ✅ | **❌ 전부 없음** |

§6b: PI3K 부트스트랩은 네트워크 필수이며 7분에 미완. §6d: PI3K 검열 오라클 39개 — 사실상
성립하지 않는다.

**새 패널을 열려면 QSAR 자산 한 벌을 통째로 만들어야 하고, 그 경로가 부러져 있다.**

### 5b. 도킹은 학습 데이터 0으로 점수를 낸다

| 채점기 | 필요한 것 | 새 타깃에서 |
|---|---|---|
| ECFP4 + GBM | 측정 분자 수천 개 | 불가 |
| **도킹** | **구조 1개** | **가능** |

구조는 AlphaFold DB에 사실상 모든 인간 단백질이 계산되어 있다(ROADMAP §7이 ColabFold를
불필요하다고 적은 이유).

### 5c. 같은 코드, 패널에 따라 다른 자리

```
데이터 풍부 (JAK)
  Tier 0 → 0.5 게이트 → Tier 1 회귀+갭 → [Tier 1.5 도킹] → Tier 2
                                            확인용, 한계적 개선

데이터 없음 (신규 패널)
  Tier 0 → [도킹] → 순위
              유일한 채점기, 있고 없고의 차이
```

### 5d. PI3K는 이미 시험대다 — 가설이 아니라 실재

PI3K는 **모델은 없는데 정답은 있다**: `cross_measured` 1,500행.

> **zero-shot 시험:** PI3K QSAR 모델을 하나도 만들지 않고 도킹만으로 1,500개를 순위
> 매겼을 때 실측 갭과 얼마나 맞는가?

베이스라인도 이미 측정되어 있다 — §4d LOTO의 unseen 중앙값 **0.472**. 도킹이 그것을 넘으면
"자산 0인 타깃에 쓸 수 있다"가 측정으로 성립한다.

**주의:** D5 금지는 PI3K에서도 유효하다 — 결합 여부만, 선택성 순위는 아니다. 따라서 위
zero-shot 질문은 갭 상관이 아니라 **결합 여부 판별**로 다시 써야 한다. 이것이 §8의 열린
질문 중 하나다.

## 6. 네 자리의 역할

| | 파이프라인 위치 | 입력 → 출력 | 바꾸는 결정 | 규모 한계 | 새 패널에서 |
|---|---|---|---|---|---|
| **G-1 도킹** | Tier 1.5 (게이트 뒤) | SMILES 300 + 구조 3개 → vina/CNN 점수 + 포즈 | 결합 여부 재확인. **갭·선택성 순위는 불변(D5)** | shortlist | ✅ 즉시 |
| **G-2 표현학습** | Stage 2 (모든 층의 입력) | 기존 데이터 그대로 → 학습된 표현 | 전부. 채택 시 `model_id` 전부 변경 = **G0 이벤트** | 전 규모 | ⚠️ 데이터 필요 |
| **PLIF 모델** | G-1 뒤 (포즈 재활용) | G-1 포즈 → 접촉 잔기·상호작용 유형 | 결합 여부 판별 표현 | shortlist | ✅ 도킹을 따라감 |
| **G-3 생성** | Stage 3 | 시드 스캐폴드 → 신규 SMILES | 루프 유입 분자 | — | ⚠️ 채점기 의존 |

**PLIF가 흥미로운 이유:** §2b의 토이 예시에서 ECFP4는 `코어–CH₃`(활성)와
`코어–CH₂CH₃`(비결합)를 거의 같은 벡터로 본다. PLIF는 전자가 힌지에 수소결합하고 후자가
게이트키퍼와 충돌한다고 본다. **§2b가 없다고 지목한 정보가 정확히 이것이다.**

의존 관계:
```
CPU 프로브 ─┬─ 통과 → G-2
            └─ 실패 → 게이트 학습 목표 재정의 (GPU 불필요)

G-1 ─┬─ 통과 → PLIF(별도 사전등록), G-3 개방
     └─ 반증 → 포즈·접촉 그림 전용 강등
```

**불변 원칙: GPU는 커밋된 자산을 만들고, 배포 앱은 그 자산을 CPU로 읽기만 한다. 앱이 GPU를
호출하는 일은 영구히 없다.**

## 7. 착수 전 5가지 — 채택된 추천안

프로젝트 오너가 아래 다섯을 채택했다(2026-08-09). 착수 시 이대로 간다.

### 7.1 리셉터 — 아이소폼당 1개, 세 구조를 같은 기준으로 매칭

앙상블(×3~5)이 아닌 이유: 비용, 그리고 결합 규칙(최고점? 평균?)이 또 하나의 자유 손잡이가
되어 G8과 충돌한다.

선택 기준을 미리 고정한다: Homo sapiens 키나아제 도메인 · ATP-site 저해제 결합(홀로) ·
해상도 ≤ 2.5 Å · 포켓 내 루프 결손 없음 · DFG-in · **세 아이소폼 모두 같은 기준 통과**.

이 실험의 질문은 아이소폼 *간* 비교이므로, 해상도나 구조 상태가 아이소폼마다 다르면 그
차이가 도킹 점수 차이로 새어든다.

**검증:** 공결정 리간드를 재도킹해 **RMSD ≤ 2 Å** 요구. 라이브러리 밖 데이터이므로 G8을
만족한다.

### 7.2 양성 팔 — (MW, logP) 매칭 활성 414개 ★ 가장 중요

**도킹 점수는 중원자 수와 강하게 상관한다.** 대부분의 스코어링 함수에서 큰 분자가 좋은
점수를 받는 잘 알려진 아티팩트다. 양팔의 물성이 맞지 않으면 이 실험은 결합이 아니라
**분자량을 재게 된다.**

`build_negatives`가 게이트 음성을 만들 때 이미 (MW, logP) 12×12 분위 매칭을 쓴다
(`negatives._matched_indices`). **같은 규율을 재사용한다.**

출처: eval fold(2020년 이후) 실측 활성 3,433개 중 매칭 추출 — 게이트·회귀 모두 보지 않은
분자다.

비용: +1,242 → 총 **2,484회, 세션 2개**.

### 7.3 소프트웨어 — gnina 1회 실행으로 두 점수 회수

gnina는 Vina 방식으로 포즈를 탐색한 뒤 CNN으로 리스코어링한다. **한 번 돌리면 두 점수가 다
나오고 추가 비용은 0이다.**

이것이 주는 것: **"CNN 리스코어링이 물리 점수를 이기는가"를 이 과제에서 직접 측정.**
이기지 못하면 GPU가 애초에 필요 없었다는 뜻이고, 그것도 값진 결과다.

### 7.4 G8 커밋 시점 — 라이브러리 밖 파일럿 → 설정 커밋 → 그다음 414

ROADMAP이 명시적으로 허용한다("설정 결정에는 라이브러리 밖 데이터를 쓴다").

파일럿 대상: 공결정 리간드 3개(재도킹 RMSD) + PDB에 복합체가 있는 공지 JAK 저해제 소수.

커밋 순서를 **파일 존재로 증명한다**:
```
1. assets/jak/docking_config.json + redock_rmsd.json   ← 커밋 (T1)
2. ... 414 도킹 ...
3. assets/jak/docking_scores.parquet                   ← 커밋 (T2 > T1)
```

### 7.5 산출물 — parquet 한 장

`assets/<panel>/docking_scores.parquet`

| 컬럼 | 이유 |
|---|---|
| `inchikey`, `smi` | 봉인 414·양성 팔과 조인 |
| `isoform` | 3행/분자 |
| `arm` | `negative` / `positive` — 2-arm이 데이터에 박힌다 |
| `score_vina`, `score_cnn` | 7.3의 무료 A/B |
| **`config_hash`** | **설정을 모르면 점수를 못 읽게** |

**포즈는 커밋하지 않는다**(용량). 최종 보고에 쓰는 shortlist 것만 별도 커밋.

## 8. 열린 질문 — 착수 전 답해야 함

### Q1. G-1의 범위

| | 범위 | 세션 | 주장 |
|---|---|---|---|
| A | JAK만 (414 + 매칭활성 414) | 2 | 확인층으로 유효한가 |
| **B** | **JAK + PI3K zero-shot** | 3~4 | + 자산 0으로 새 패널을 열 수 있는가 |
| C | PI3K만 | 2 | 일반화만 |

**작성 시점의 추천은 B.** 근거 셋:
1. `src/docking.py`를 패널 인자로 쓰는 비용은 처음에 하면 0, 나중에 고치면 리팩터
2. §6이 기록한 "명목상 일반화"를 실질로 바꾸는 유일한 실험
3. JAK에서 반증돼도 PI3K에서 성립하면 도킹은 살아남는다 — 자리가 바뀔 뿐

B는 합격 기준을 **두 개** 미리 써야 한다(G8). 두 기준이 서로 대체재가 아니므로(다른 패널,
다른 질문) 자기충족은 아니다. **다만 PI3K 쪽 기준을 D5와 모순 없이 쓰는 방법은 아직
정해지지 않았다** — §5d의 주의 참조.

### Q2. PLIF 사전등록 — 채택: A안

G-1과 같은 데이터를 쓰므로 "도킹 점수가 실패하면 PLIF로 갈아탄다"가 되면 자기충족이다.

**A안 채택:** 포즈는 저장하되 PLIF 실험은 **자체 합격 기준을 먼저 커밋한 뒤** 진행한다.
포즈 저장은 사실상 공짜이므로 GPU 세션을 아끼면서 규율도 지킨다.

### Q3. G-2 착수 게이트 — CPU 프로브 (미실행)

GPU 세션을 태우기 전 반드시 돌릴 CPU 30분 실험:
